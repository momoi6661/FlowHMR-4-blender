# FlowHMR Blender 插件

源码推理后端保持在项目的 uv 环境里。Blender 负责素材、片段、选人、预设和骨骼动画；
推理在独立进程中执行。插件不需要向 Blender 安装 PyTorch、CUDA 或 FBX SDK。

## 安装和打开

运行 `uv run python tools/windows/package-blender.py` 生成
`dist/FlowHMR-Blender.zip`。在 Blender 的偏好设置 → 插件 → 从磁盘安装中选择 ZIP，
无需解压，启用 **FlowHMR 动捕**。3D 视图按 N，打开 **FlowHMR** 标签。
插件 ZIP 不记录打包机器的源码目录。插件可以连接已经运行的 FlowHMR 后端；如果需要由插件启动后端，
请在插件偏好设置中明确选择后端源码目录和 Python。这样插件可以独立更新，不会绑定某个项目副本或项目版本。
更新时安装同名 ZIP 即可；若当前 Blender 会话已经加载旧插件，先保存工程，安装后自行重启 Blender。
插件使用同一个 `flowhmr_bridge` 模块名，不需要保留多个版本的 ZIP。

## 推荐操作

1. 3D 视图按 N，打开 FlowHMR。主界面是常驻侧栏面板，分为“素材、任务、骨架、设置”四页，无需切换工作区。
2. “素材”页统一选择视频和图片，支持一次多选、拖入 FlowHMR 侧栏或播放器。已导入列表默认折叠，保存在当前 .blend 中；切换素材会记住各自的片段范围。“移除”保留原文件和任务。
3. 面板显示静态封面。视频点击“打开视频播放器”，可在底部拖动选段两端，或用工具栏“起点 / 终点 / 选段”设置提取范围；主面板也可输入起止秒数。图片点击“放大图片 / 修正人物框”，显示静态预览、分辨率，不显示播放和片段控件。
4. 点击“开始 AI 识别”或“提取图片姿势”，检查人物缩略图并勾选，可多选。需要修正时点该人物的“修正人物框”，在预览中拖出完整人物框，再确认生成。图片修改整张图的人物框；视频在当前帧添加修正锚点，多个锚点之间插值，范围外保持原检测。
5. 默认只生成 FlowHMR 标准骨架和动作，不创建 ARP 控制器，也不自动匹配任何外部装备。需要时在“骨架”页手动导入自己的角色，识别骨骼并烘焙一个新的 Action。低频生成参数默认折叠；“设置”页管理环境、模型及手动释放显存。
6. “导入”支持 FBX、GLB/glTF、blend；VRM 需要已启用 Blender 的 VRM 导入插件。单骨架自动设为目标，多骨架需手动选择。导入 blend 只追加角色数据。
7. 标准骨架用于检查原始结果；已有角色选项把动作写入新 Action。多人结果添加到一个角色时，先从“结果人物”选择一人。同一条历史动作可依次添加到不同角色。

角色导入用于预览和骨架重定向。当前 FlowHMR 根据视频推理标准人体动作，不以用户角色网格或任意骨架作为 AI 推理条件；选择角色不会改变 AI 权重。

“任务”页共用项目历史，支持打开原素材、恢复参数、导入动作、重新生成和删除记录。
“Web 版”和“设置”页的“视频 / 动作对照工作区”为可选入口。
AI 模型由独立后端常驻，关闭面板、播放器及更新插件时不自动停止后端；在“设置”页手动释放或停止。

图片在项目 `.cache/blender-media` 内生成供解码器读取的缓存，界面始终以图片呈现。
最新源码后端仅从图片提取一帧姿势，不从单张图片推断运动过程。开启人物选择后，单人也可以修正框：拖动框内移动，拖角点或边缘缩放，框外拖动重画；可连续调整，Esc 取消当前拖动，撤销按钮恢复自动框。
图片保留“地面与接触”配置：自动接触仅按最低脚底探针整体升降到支撑地面，保留关节旋转和水平位置；
保留浮空不进行这一放置。旧后端不支持图片地面配置时会提示重启源码后端，插件不会自动重启或释放模型。原始图片不修改。
旧图片任务即使保存了 30 帧，插件重新添加时也仅取第一帧原始姿势；绑定角色同样只写一帧关键帧，
不修改历史结果、不重新推理。已经导入的旧 Action 保留，需要从任务页重新添加图片姿势。
“选择视频 / 图片”统一选择素材，也可拖入；支持多选，PNG、JPG/JPEG/JFIF、WebP、BMP、TIFF 均可导入。
图片先校正 EXIF 方向；选择“自动适配”时，最长边不超过 1920，小图短边尽量达到 256，最多放大 4 倍；
也可选择“保留原图尺寸”，不进行放大或缩小。切换尺寸后点“应用”重新准备当前图片。
编码仅补齐偶数尺寸，不拉伸或裁切。面板显示原图与识别尺寸。短边不足 32 像素、超过 6400 万像素或损坏图片会给出具体提示。
低分辨率会提醒换用清晰原图；尺寸放大不能恢复失焦、运动模糊或遮挡丢失的细节。图片仅提取姿势，不生成原图里不存在的动作。

“视频 / 动作对照”保留为可选的大画面对照：原视频、三维结果和共享时间轴。
打开小窗、选择素材和导入结果不会自动切换原 Blender 布局。
播放器是 Blender 自带的独立编辑器窗口，可自由移动、缩放，关闭后任务仍由后端继续执行。

## 项目任务历史

“任务”页会启动或连接共用后端并同步项目记录，网页和插件共用同一份任务。
可以按名称、素材或任务 ID 搜索，并按状态筛选已加载记录。管理模式支持勾选后批量删除。
列表显示原素材的小封面、名称、类型、时间、人数、帧数与状态；选中任务显示较大封面及片段信息。
历史只保留了 input.mp4 名称的旧记录无法恢复原文件名，仍可通过封面区分。封面获取失败不影响打开和导入任务。
图片上传会保留原图名称与后缀，解码容器名形如“姿势.webp.mp4”，旧后端也能保留图片身份。
已完成任务若缺少素材类型，网页与插件可从结果元数据恢复显式标记；不按视频时长或帧数猜测类型。

- 打开：恢复原素材预览、片段范围和生成参数，已完成动作可随后添加到角色。
- 添加动画：使用当前“目标骨架”自动匹配并写入新 Action；未指定目标时显示标准骨骼。
- 沿用原配置重跑：使用历史任务的素材和原参数，重新选择人物，创建一个新任务。
- 素材页“按当前配置重新生成”：打开任务后，按当前面板中的片段、地面、手部及生成参数创建新任务；保留原任务与已导入的动作。
- 删除任务：正常模式删除当前高亮项，管理模式可以勾选后批量删除；确认后删除项目记录和对应结果文件。运行中的任务跳过，已导入 Blender 的角色与动画保留。

导入前可填写“骨骼名称”和“动画名称”，留空自动命名。多人结果追加人物编号；
映射到已有角色时，动画名称用于新 Action。

多人动作映射到一个角色时，先选择具体结果人物，再点“映射并添加到目标骨架”；默认生成阶段不会自动执行这一步。
主面板的吸管可使用角色骨架或已绑定身体；骨骼对应细节在“骨架”页调整。

人物框修正需要新版源码后端的 `/select-boxes` 接口。若后端仍运行旧代码，插件会提示需重启后端，
不会丢弃修正后直接生成。请在当前任务结束后自行重新启动后端；更新 ZIP 不会替你重启或释放 AI 模型。

## 已有角色骨骼适配

插件不会把 FlowHMR 结果导出成 ARP 控制器，也不会在生成完成后调用 ARP 的“匹配装备”。
默认结果就是自己的标准骨架；如果要给已有角色使用，插件只把识别到的动作按骨骼对应关系烘焙成新的 Action，原始标准骨架仍保留用于检查。

支持常见的 Rigify、Mixamo、VRM、Unreal / MMD 命名；复杂 IK、附加约束和自定义驱动仍需要在“骨架”页检查对应关系。

自动匹配避免一根目标骨骼被多个源关节重复占用。已有角色会按腿长调整根位移，保留角色初始站位，
为不同骨骼方向校正旋转，并迭代求解控制骨架的约束父级。无法解开的约束会给出具体骨骼名称，
并恢复原 Action 和姿势；不会静默宣称完成。原 Action 开启保留标记，后续仍能在动作编辑器中切回。
未映射的脸部、布料、附加骨骼保留原有控制关系。

多人结果先导入所有标准骨骼，保留共同时间轴和站位。已有角色一次烘焙一个人物：
选中该人物的标准动捕骨骼，指定目标角色，点击“将选中动捕骨骼烘焙到角色”。
标准骨骼身体使用线性蒙皮供检查动作，不包含 SMPL 的姿势修正形变；可以单独关闭身体导入。
中性、男性、女性标准身体可以在模型已安装时选择。
标准骨架补齐骨盆、肩部和手掌等分叉的显示连接，与 Web 的关节点连线一致。
这些额外连接不可选中且不参与变形，原来的 52 根变形骨骼和动作通道保留。
已导入的旧标准身体或骨架可在“骨架”页点击“补齐骨骼显示连接”，无需重新生成，支持撤销。

## 帧率与已有动画

推理统一使用 30 FPS，导入沿用当前 Blender 场景帧率，用亚帧关键帧保持时长。
例如在 24 FPS 场景里导入 30 帧动作，关键帧间距是 0.8 个场景帧。
不会把整个场景改成 30 FPS。结果放在独立集合，已有角色的动画写进独立的新 Action。
直接导入完成后选中骨骼；同步烘焙较长动作可能需要等待 Blender 完成数据写入。

## 地面、跳跃与浮空

标准预览角色的静止 T 姿势以脚底为零平面，骨架与身体使用相同的基准。
导入时补偿根骨骼位移，保持原动作的世界位置、跳跃与浮空轨迹。
已经导入的旧角色可选中标准骨骼或身体，在“骨架”页点击“以当前姿势对齐地面”：
只整体移动人物，使当前姿势最低点落在零平面，不修改关键帧或逐帧压平动作，支持撤销。
该按钮用于标准动捕人物；已有自定义角色继续沿用原始站位与高度偏移。

生成页用一个“地面与接触”选择代替“减少滑步”开关：

- 自动接触：按支撑脚修正滑步和地面穿透，沿用后端已有的跳跃检测。
  跳跃检测依赖可见的起跳、落地与重建轨迹，不能保证所有腾空片段均判断正确。
- 保留浮空：关闭地面与脚掌贴合修正，适用于飞行、悬浮和只截取腾空的片段。
  保留的是 AI 识别出的轨迹，不会自动恢复识别时丢失的高度。

更改模式或支撑地面后，需要创建新生成任务；已经修正过的结果不能通过切换选项还原。
历史列表“沿用原配置重跑”使用原任务参数；需要改模式时先“打开”任务，再改模式并在素材页点击“按当前配置重新生成”。
旧工程和 Web 历史中的接触修正开关会自动显示为对应的模式。

给已有角色添加动作时，“保留水平位移”和“保留上下运动”分别控制水平移动与跳跃升降。
默认均开启。原地跳跃可关闭水平位移并保留上下运动，坐标按世界竖直方向处理。
独立函数的旧 `root_motion` 调用仍保持原有语义；插件界面为上下运动单独传参。
“高度偏移（米）”整体升降本次导入的标准骨骼或目标角色动作，不改变跳跃幅度。
目标角色沿用原始站位并接收相对首帧的位移；源动作整段浮空时，需按场景设置高度偏移。
修改位移和高度后重新“添加动画”即可，不需要重新 AI 推理，原 Action 会保留。

“生成参数”中的支撑地面用于生成修正；“显示参考地面 / 参考地面高度”控制 3D 视图中的参考网格。
参考网格不创建场景物体、不写关键帧、不参与碰撞或导出；移动它不会抬起或压低人物。
目前尚未接入楼梯等多层支撑和时间轴手动腾空区间。

## 手脚预设

选中导入的动捕骨骼或身体，把时间轴移动到需要的姿势，命名并保存手或脚。
保存和导入的预设自动写入项目内的 `output/pose_presets/*.json`，网页与 Blender 共用；
面板显示实际目录，刷新后同步多个场景中的列表。支持 JSON 导入、导出、删除。
手动导出默认定位到 `output/pose_presets/exports/`，可以自行选择保存位置。
保存的是该人物当前动作帧的原始生成姿势，不包含 Blender 中手动改动后的骨骼姿态。
应用区间为人物本身的动作帧，从 1 开始，与 Blender 场景帧不同。
可以使用当前帧或整段动作，调整强度和边界过渡，生成独立的修正版，再自动导入或烘焙。
预设只编辑选定关节的旋转，不会生成门把手、地面等外部物体的 IK 接触约束。

## 显存与环境

默认自动决定 SAM 批次，HaMeR 继续使用后端的低显存批次与重试策略。
AI 推理模型默认保留，任务成功、失败或停止后不自动卸载，下次复用已加载的模型。
低显存设备按推理阶段在系统内存和 GPU 之间调度模型，避免所有模型同时占用显存；不会每次重新从磁盘加载。
点击“释放 AI 模型”才手动卸载；它不删除 Blender 场景中的角色、身体或骨骼。
手动卸载会拒绝仍在运行或收尾的任务。CUDA 上下文在后端进程存活时仍可能保留少量显存。
“退出后端 / 中断所有任务”会停止当前本机地址上已确认的 FlowHMR 服务及其子进程，
包括由插件、桌面程序或终端启动的服务。即使正在识别或等待 HTTP 返回，也可以退出；
退出后检查端口已关闭。重新启动会重新加载 AI 模型。

高级参数折叠保存：生成步数、种子、引导、平滑、手部采样、显存批次、地面和贴地强度。
模型就绪状态与环境路径在插件偏好设置中查看；权重继续保存在源码项目的 models 目录。
